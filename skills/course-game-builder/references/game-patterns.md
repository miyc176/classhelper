# Game Pattern Guide

Choose mechanics that make the learner operate on the knowledge, not merely recognize text.

## Mechanic Selection

| Knowledge shape | Strong mechanics | Avoid |
| --- | --- | --- |
| Terms and definitions | clue cards, matching, memory, rapid review | plain multiple choice only |
| Categories or properties | sorting lanes, drag/drop bins, odd-one-out | long reading screens |
| Ordered processes | sequence repair, timeline, path builder | random question order |
| Formulas or calculations | generated cases, parameter sliders, step feedback | fixed single-answer quiz |
| Diagram labels | hotspot labels, connection tracing, reveal layers | text-only rewrite |
| Cause/effect | small simulation, what-if challenge, consequence chain | isolated flashcards |
| Misconceptions | diagnose error, choose fix, compare examples | vague right/wrong feedback |

## Design Rules

- Build the real game as the first screen.
- Keep one dominant task per mini-game.
- Use course visuals when they carry instructional meaning; recreate diagrams in HTML/CSS/canvas only when image reuse is unavailable or unclear.
- Make distractors plausible and source-grounded.
- Explain feedback using the extracted knowledge point id and statement.
- Prefer short rounds with visible progress over long forms.
- Include a teacher-friendly reset button.

## Suggested Game Set

For a full lesson, prefer 2-4 small games instead of one overloaded game:

- Warm-up recall game for vocabulary and facts.
- Core mechanic game for the central procedure, system, formula, or diagram.
- Misconception game for common errors.
- Exit-ticket challenge that mixes concepts.

For classic or arcade-style requests, read `classic-game-patterns.md` and prefer recognizable mechanics such as whack-a-mole, memory cards, answer-gated tic-tac-toe, flappy true/false gates, shooter classification, and knowledge organization puzzles.
